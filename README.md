# mid_tempo_to_flp

> [!NOTE]
> **Project 100% Generated by Artificial Intelligence**
> This repository was developed entirely using AI tools. All code, architecture, and documentation were generated automatically. [PyFLP](https://github.com/demberto/PyFLP) hasn't been updated in a while, so I had to create a parser from scratch.

> [!WARNING]
> Tested on **v26.1.7.5653**, it may stop working after a major update.

Inserts a fractional-BPM tempo automation clip (Hold mode) into an FL Studio `.flp`
project from a MIDI file's tempo map.

Works around the decimal BPM rounding FL Studio applies when importing MIDI.

## Requirements

- Python 3.8+

## Usage

([Youtube video link](https://www.youtube.com/watch?v=_ruueEe3mfs))

```bash
python mid_tempo_to_flp.py --flp project.flp --mid song.mid --out output.flp
```

| Option  | Description |
|---------|-------------|
| `--flp` | Input FL Studio project (with notes already imported) |
| `--mid` | Source MIDI file to read the tempo map (`set_tempo`) from |
| `--out` | Optional. Output path. Default: `<flp>-<mid>.flp` |

## Example

```bash
python mid_tempo_to_flp.py --flp clean.flp --mid "Pieces of You.mid" --out out.flp
```

Output:

```
wrote out.flp
  automation channel IID: 3 | points: 174 | clip length: 43249 PPQ | clip id: 2
  ppq=96 midi division=192
```

## What it does

1. Reads all `set_tempo` events from the MIDI and converts them to beats (`tick / division`).
2. Adds an automation channel labeled "Tempo" to the FLP.
3. Writes the automation points in **Hold** mode (`value = (bpm - 10) / 512`,
   range 10–522 BPM).
4. Adds the matching clip to the playlist, covering the whole song.
5. Updates the header (channel count) and the `FLdt` chunk size.

No other events are touched: the output is identical to the input except for the
automation channel and the playlist item.

## Notes

- The tempo map may extend slightly past the last note; in that case the clip sticks
  out a bit beyond the pattern (the points themselves are still correct).
- The input `.flp` must be a valid FL 26+ project (it is parsed at the binary level;
  pyFLP is not used because it is incompatible with FL 26 / Python 3.12).
